## Summary

Requirement-level coverage (prd-align rounds 1–3) is genuinely tight, and most execution-level work is well owned: every slice-table outcome cell carries named verifiers, the TESTS checklist contract is concrete, the migration ledger discipline is a blanket per-slice rule, and rollback coherence is mostly by-construction (ratchet edits ride slice commits, Design position 6). But the audit found **4 [must-fix] and 7 [should-fix]** completeness defects that create-beads would materialize as holes:

- **F1 (must-fix):** the staged final gates' auto-activation predicate ("once the allowlist reaches ∅") contradicts the plan's own arithmetic — allowlist is ∅ **after S5**, while the wrapper stays in the payload until S6's deletion commit (repo-verified: both platform entry lists import `bem:jquery` directly). As written, the no-jquery/CONST-P1 final assertions go binding — and red — between S5 and S6. This is a NEW S5→S6 boundary bug adjacent to, not a re-litigation of, prd-align-1 GA-F2 (which fixed S1–S5 staging).
- **F2/F4 (must-fix):** three tooling artifacts the plan narrates — generated platform entries ("S0–S1 tooling"), the `.deps.js` schema+resolution lint, and the entity-converter unification — appear in no slice-table outcome cell, so create-beads schedules them nowhere; the keyboard__codes payload-parity assertion (OQ-6) hangs on an unowned REQ.
- **F3 (must-fix):** block-level .md/.ru.md docs (51/29 files) are a doc surface the plan mutates in S1/S2/S3/S6 with no owner, no fence coverage, and no carrier for the NEW public `env` module's docs.
- Should-fixes: plugin validation timing "(S0/S6)" ambiguous; doc-parity fence missing from CI wiring; exports-narrowing and orientchange-transport breaks lack named MIGRATION lines; bench v5-base baseline capture unscheduled; bundle-gate capped-artifact set unenumerated (barrel uncapped); S2's "S1 soft" edge missing from the Bead DAG line.

## Findings

### [must-fix] F1 — Staged final gates' activation predicate contradicts "∅ after S5"; CI goes red between S5 and S6
- **Sections:** Executive Summary — "the no-jquery-in-artifact assertion and the jquery peer/dev-dep removal check **activate at S6**, when the CONST-P1 allowlist reaches ∅" AND, same summary, "**∅ after S5**, making S6 purely deletion"; Key Components 10 — "**activate at S6** (or auto-activate once the allowlist reaches ∅)… short-circuit to preview output + exit 0 **while the allowlist ≠ ∅**, binding otherwise"; Key Components 13 — "until the allowlist reaches ∅ and is conclusive (binding) at S6".
- **Slices:** S5, S6 (predicate authored S0).
- **Evidence:** the wrapper remains in the payload until S6's deletion commit — `build/platforms/desktop.js:30` and `build/platforms/touch.js:30` both `import 'bem:jquery'` directly, and D-8/KC 8 generation reproduces the hand lists; S5 only removes the last *consumers* (allowlist = ∅) while `common.blocks/jquery` and its entry imports survive to S6. Under the written guard ("allowlist ≠ ∅ → preview"), the gates flip to binding the moment S5 merges and immediately fail (jquery legitimately in artifact; "wrapper dirs gone" legitimately false) — S5→S6 CI red, breaking C2/G7, the exact failure class prd-align-1 GA-F2 eliminated for S1–S5. Revert hazard too: with an ∅-trigger, reverting S6 alone (wrapper restored, allowlist stays ∅) wedges every gate binding-red.
- **Suggested fix:** change the activation predicate to **wrapper-block existence, not allowlist emptiness** — KC 10 + KC 13 guard form: "short-circuit to preview + exit 0 while `common.blocks/jquery` exists, binding once the wrapper dirs are gone (first binding-green commit = S6's deletion commit)"; Exec Summary parenthetical: "(activate when the wrapper block is deleted at S6 — the allowlist is already ∅ from S5)". Self-reverting by construction under slice revert.

### [must-fix] F2 — Generated-entry machinery has no single owning slice ("S0–S1 tooling")
- **Sections:** Key Components 8 — "Init registry (S0–S1 tooling) — platform entry modules **generated from the plugin's scan registry** (replacing hand-maintained ordered import lists)"; Open Questions 6 — "the **S0/S1 generation REQ** must either reproduce it (payload-parity assertion vs today's hand lists)"; Decision D-8.
- **Slices:** S0 (recommended owner), S1.
- **Evidence:** no slice-table outcome cell mentions entry generation; the S0 cell's "named-export barrel v1 (existing modules)" could be hand-written, and S1's cell never mentions it — yet create-beads consumes the slice table, and the keyboard__codes payload-parity assertion (KC 8, OQ-6, Non-Goal-frozen keyboard) attaches to a REQ that no slice carries. An engineer would discover mid-S0/S1 that nobody owns replacing `build/platforms/{desktop,touch}.js`.
- **Suggested fix:** pin the owner — recommend S0 (it already owns the verification fence, specs/ convention, and needs the payload-parity assertion from day one). S0 outcome cell gains: "platform entries generated from the plugin scan registry (payload-parity assertion vs today's hand lists incl. `keyboard__codes`; hand lists deleted)". KC 8's tag "(S0–S1 tooling)" → "(S0)". OQ-6's "S0/S1 generation REQ" → "S0 generation REQ".

### [must-fix] F3 — Block-level doc surface (51 .md / 29 .ru.md) has no owner; new public `env` module has no doc carrier
- **Sections:** Implementation Plan TESTS checklist contract (four items, none docs); Key Components 13 — "Doc-parity fence (**MIGRATION/CHANGELOG** en↔ru section anchors) in S0"; S6 row (docs pass scoped to README bounded section + common.docs API pass only); Risks docs row (same scope).
- **Slices:** S1 (env NEW public module; ua rewrite), S2 (dom/idle rewrite, winresize deletion), S3 (loader rewrite, `loader_type_bundle` deletion), S6 (jquery/__config/page elems deletions).
- **Evidence:** repo has block-level docs next to the very blocks the plan rewrites/deletes: `common.blocks/ua/ua.{en,ru}.md`, `dom.*.md`, `idle.*.md`, `loader.*.md`, `jquery/jquery.{en,ru}.md`, `jquery/__config/jquery__config.ru.md`, `i-bem-dom.*.md` (51 .md / 29 .ru.md total). The plan names every other doc surface (README, MIGRATION, CHANGELOG, common.docs guides, jsdoc via the CI docs job, package.json, LICENSE) but never block mds; the fence covers MIGRATION/CHANGELOG anchors only. `env` is explicitly a NEW public module (Q5 exception) — shipping it with no doc requirement is a hole the S1 engineer hits, and stale ua.md would document removed fields.
- **Suggested fix:** add item 5 to the TESTS checklist contract: "**Docs Δ** — block `.md`/`.ru.md` updated/deleted with the block; new public modules ship docs (en+ru)". Name carriers in slice cells: S1 "env docs + ua alias/removed-fields note"; S2/S3 "block docs ride the rewrite/deletion"; S6 "jquery/__config/page md deletions ride the deletions". Consider extending the S0 doc-parity fence scope to block-md en↔ru pairs at S0 spec-craft.

### [should-fix] F7 — Exports-map narrowing has no named MIGRATION line
- **Sections:** Design position 2 — "The exports map narrows `"./*"` → `"./common.blocks/*"` (+ enumerated entries) in S0"; Design position 3 (enumerates only the root-export break: "S0's MIGRATION cell carries the line").
- **Slices:** S0.
- **Evidence:** current exports map is `"./*": "./*"` — today every root-relative path resolves (`desktop.blocks/…`, `touch.blocks/…`, `test/…`, `common.docs/…`); after narrowing they throw `ERR_PACKAGE_PATH_NOT_EXPORTED`. A C4-visible break with an owning slice but no named cell line — the doc's own pattern (position 3, CC-F2 fix) is to enumerate each break.
- **Suggested fix:** Design position 3 (or S0 row): "S0's MIGRATION cell also carries the exports-narrowing line: root paths beyond the enumerated entries + `./common.blocks/*` no longer resolve."

### [should-fix] F8 — orientchange transport change (jQuery synthetic → native CustomEvent) not enumerated as a break
- **Sections:** Key Components 1 — "one native `resize` listener dispatching `CustomEvent('orientchange', {detail:{landscape,width,height}})` — firing guard **preserved**"; env/ua surface — "`orientchange` CustomEvent on window".
- **Slices:** S1.
- **Evidence:** today `touch.blocks/ua/ua.js:79` fires `$win.trigger('orientchange', {...})` — a jQuery synthetic event reaching only jQuery-bound handlers; a native `dispatchEvent` CustomEvent is invisible to `$(win).on('orientchange')` registrations, and the payload moves from the trigger args/Event object to `event.detail`. "Guard preserved" covers the firing heuristic, not the listener contract. In-repo consumer (`ua__dom`) is rewritten in-slice; external listeners (hard fork, single consumer — low impact) break silently. Undocumented in the plan's break inventory.
- **Suggested fix:** KC 1 + S1 MIGRATION cell add the line: `$(win).on('orientchange', (e, data) => …)` → `window.addEventListener('orientchange', e => … e.detail.landscape …)`.

- **Suggested fix:** S2 outcome cell gains: "v5-base reference capture (build @ tag v5-base; record B1–B6 baseline numbers into the bench config/specs/); thresholds evaluated against it".

Likewise nothing states whether per-slice re-measurement is required or forbidden (in fact the payload's composition is unchanged until S6's deletion — jquery rides the entries throughout, cf. - **Suggested fix:** KC 10 + S0 spec-craft: "capped artifacts enumerated: `dist/{desktop,touch}/bem-core.mjs` + `dist/index.mjs` (or payloads-only with recorded rationale); caps re-measured only at S6 (mid-series composition unchanged while the wrapper remains in the payloads)".

### [should-fix] F11 — S2's "S1 soft" dependency edge missing from the Bead DAG spec
