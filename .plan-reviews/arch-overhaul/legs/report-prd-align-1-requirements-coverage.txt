# PRD-align-1 · requirements-coverage (review_id=arch-overhaul, review_phase=prd-align-1, review_leg=requirements-coverage)

## Summary

Walked all 23 requirements (G1–G7, C1–C6, binding amendments Q1–Q10) from
`.prd-reviews/arch-overhaul/prd-draft.md` against design-doc baseline v1
(`.designs/arch-overhaul/design-doc.md`), requirement by requirement.

Result: **19 COVERED, 4 PARTIAL, 0 MISSING** — 2 [must-fix], 3 [should-fix].

The baseline is strong: all ten Q-answers are concretely landed (anchor tag in
S0, outright wrapper deletion D-1, full public-API contract in Interface,
inherit freeze D-2, scoped env + one-release ua alias, benchmarks in S2,
bundle-loader deletion D-1/Q7, chromium-only matrix D-15, one 6.0.0 D-12,
pure-registry BEM events D-3 with the three parity caveats), and the slice
discipline (7 slices, all ≤12 REQ, per-slice MIGRATION + allowlist deltas) is
explicit and machine-checkable.

The two must-fixes are cheap documentation reconciliations, not design rework:
(1) PRD G5/OQ3's "pointerevent normalization" is absent from the design doc
with no reconciliation — repo grep shows no pointer code exists in the fork
@ f2ab61e, so the PRD premise is stale and the design doc must say so;
(2) PRD G3's "timeout" sub-clause of loader semantics is never dispositioned —
repo grep shows loader_type_js has no timeout today, so again a reconciliation
note suffices. Neither blocks the design's soundness; both would strand a
future requirements-walker (plan-review, create-beads) exactly where I hit the
wall.

## Findings

### F1 [must-fix] — G5 / PRD-OQ3: "pointerevent normalization" absent from the design doc, no reconciliation
- **PRD trace:** G5 ("The monolith split into cohesive internal modules (live collection/ranges, event delegation, **pointerevent normalization**, init lifecycle)"); PRD Open Question 3 (pointerevent normalization ownership — "where does it live … does it remain public?").
- **Design-doc anchor:** Key Components 6 — the decomposition list `params-store / entity-index / collection-cache / dom-facade / find-engine / events-dom / events-bem / init-lifecycle` contains no pointer concern; the delegation-engine description (Key Components 4) maps only "focus/blur → focusin/focusout"; the design doc's own Open Questions (1–9) do not mention it; zero occurrences of "pointer" in the whole document.
- **Repo evidence (fork @ f2ab61e, grep-verified):** `rg -ln "pointer" common.blocks/ desktop.blocks/ touch.blocks/ build/` matches only unrelated files (`functions.*.md` prose, the vite plugin). `i-bem-dom.js` has none. **No pointerevent-normalization code exists in the fork** — the PRD premise (2016 upstream memory) is stale, and the design doc's omission is factually correct but undocumented.
- **Why must-fix:** a requirements-walker in plan-review/create-beads hits this exact wall: stated G5 sub-requirement with no design coverage and no explanation. C4 parity could also be silently mis-scoped if pointer behavior is assumed to exist.
- **Suggested fix (one line):** in Key Components 6 (or beside the numbering note at the top), add: "PRD G5/OQ3 'pointerevent normalization': grep-verified absent from the fork @ f2ab61e — nothing to decompose, OQ3 void; if pointer normalization is ever needed it is an events-dom engine mapping-table concern (cf. focus/blur → focusin/focusout)."

### F2 [must-fix] — G3: loader "timeout" sub-clause never dispositioned
- **PRD trace:** G3 — "`loader_type_js` semantics (async script load, error reporting, **timeout**) provided via `import()`-based implementation".
- **Design-doc anchor:** Key Components 7 + Interface → Loader surface — "`loader(url, success?, error?)` → promise of module namespace"; async ✓, error ✓ (callback + `import()` rejection + bilingual note); "timeout" appears nowhere in the design doc.
- **Repo evidence:** no `timeout` anywhere in `common.blocks/loader/`; current `loader_type_js` exposes `get(path, success, error)` + a loading queue only — **no timeout semantic exists today**. The PRD sub-clause is itself void.
- **Why must-fix:** a stated semantic in the binding requirement inventory is uncovered; either cover it or explicitly reconcile it.
- **Suggested fix (one sentence in Loader surface):** "PRD G3 lists 'timeout': `loader_type_js` never exposed a timeout (repo-verified) — requirement void; if a timeout is wanted it is a new feature (Non-Goal) or a one-line `Promise.race` wrapper to decide in the S3 spec."

### F3 [should-fix] — G2: retained UA-driven detection not classified or justified
- **PRD trace:** G2 — "preserving the few legitimate UA-driven branches with **documented justification and tests**".
- **Design-doc anchor:** Key Components 1 + Interface → env/ua surface — lists `platform/ios/android/browser/screenSize/svg` (memoized) and `width/height/landscape` (live) without classifying which are UA-string-derived vs capability-probed, and without a justification/test requirement for the retained UA-derived getters. Q5 scoping itself is fully covered.
- **Suggested fix:** one sentence in env/ua surface classifying the getters (e.g. `platform/ios/android/browser` = UA-derived, retained because touch `ua__dom` consumers read them — justification recorded; `svg/screenSize/width/height/landscape` = capability/live probes) + an S1 TESTS entry "each UA-derived getter: documented justification + dedicated unit".

### F4 [should-fix] — C1/CONST-P5: MPL-2.0 notice preservation unmentioned
- **PRD trace:** C1 — "CONST-P5 hard fork at `v5-base` (MPL-2.0 notices intact)"; CONSTITUTION.md CONST-P5 — "Keep LICENSE.txt and file-level MPL notices intact."
- **Design-doc anchor:** Key Components 13 "Constitution checks" enumerates the P1 final predicate, CONST-P6, and the doc-parity fence — no P5; the S6 row (mass file deletion + "README/README.ru rewrite") never mentions license notices.
- **Suggested fix:** add to Key Components 13 (or the S6 row): "CONST-P5: LICENSE.txt + file-level MPL-2.0 notices preserved through S6 deletions/rewrites; S6 done-gate includes a notices-intact grep."

### F5 [should-fix] — Q3/G4: `./common.blocks/*` wildcard vs "pinned" deep-import inventory
- **PRD trace:** Q3 ("deep-imports stay public"; the public-blocks inventory); G4 (inherit frozen as internal detail).
- **Design-doc anchor:** Design position 2 — "The exports map narrows `"./*"` → `"./common.blocks/*"` … making non-public paths unresolvable" vs Interface → "Supported deep-import inventory (the pinned set)", which does not include `inherit/inherit.vanilla.js` (still resolvable under the wildcard, so "public by inventory" overstates the mechanical boundary).
- **Suggested fix:** one clarifying sentence: the wildcard is a deliberate compatibility superset; the pin test + CONST-P4 police the pinned inventory; state explicitly whether `inherit`'s deep-import path is in the public contract (pin it) or internal-but-tolerated until a future narrowing.

### Verified non-findings (no action)
- Allowlist arithmetic 1+3+2+3=9 matches the CONSTITUTION.md sdd-check allowlist entry-for-entry.
- "main vs v5" (C2) naming is coherent — v5 is the fork mainline; design cites C2 explicitly.
- `$.fn.bem` timing ("S5/S6" in DOM type contract, "`$.fn.bem` off" in S5 row) is consistent with allowlist ∅ at S5.
- Q1 "annotated" tag attribute is slice-0 spec detail, not a design-doc gap.
