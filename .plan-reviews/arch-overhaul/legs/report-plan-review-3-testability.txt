Two must-fix gaps remain, both in the staged-gate machinery the whole series leans on:

A guard bug that exits 0 forever is indistinguishable from a clean repo — a gate that can be silently skipped, with no named test anywhere.
2. **The two-directional ratchet has no named artifact and no failure-direction test.** KC 10 asserts "the gate fails … when ALLOW−JQ ≠ ∅", but @ f2ab61e the constitution check is additions-only (`comm -23`), the S0 amendment list in KC 13 names only CONST-P6 + the CONST-P1 final predicate, and no script/section owns the forgotten-shrink comparison. As written, a forgotten shrink surfaces at S6, contradicting KC 10's own claim.

Plus 12 should-fix items: mostly predicate-set definitions the S0 authored checks will need anyway (zero-jquery pattern/exclusions, notices-intact, CONST-P6 include-set, doc-fence anchor syntax/file-set), two audits that are prose rather than greps (CORS, parseHtml), the ua-alias once-warn contract with no test, the Vite half of exports-narrowing, bench gating not covering S2 itself, the S5 harness exit lacking an S5-time predicate, registration-accounting having no home, the page.examples "checked" clause, and the spike's unnamed recording artifact.

None of these require plan restructuring — every fix is a cell/section edit naming an existing verifier or tightening a predicate definition. With MF-1/MF-2 applied, the create-beads conversion can encode every done-gate mechanically.

## Findings ([must-fix] / [should-fix], each with section anchor + suggested fix)

### MUST-FIX

**MF-1 — Skip/preview guard has no test proving it can bind or go red.**
Sections: Key Components 10 ("Guard form: the final assertions short-circuit to preview output + exit 0 while (allowlist ≠ ∅) OR the wrapper block still exists OR package.json still lists jquery, binding otherwise"), Key Components 13 (same guard for the CONST-P1 final predicate), Executive Summary staged-gate bullet, CI wiring ("CONST-P1 final predicate (in its skip/preview form) ride the same `build` job from S0"). Slices: S0 (authoring), S6 (first real bind).
From S0 through S5 the guard runs only in skip mode; the bind branch first executes with real state at S6's deletion commit. A guard bug (wrong file key, inverted disjunct, path typo) yields exit-0-forever — the final assertions silently never run — and a green at S6 cannot distinguish "clean repo" from "broken guard". The assignment's own litmus: a gate that has never failed is unverified; this one cannot fail before S6 by construction, so only a fixture test can verify it. No TESTS item names one.
Suggested fix: TESTS item 2 (S0 "New") gains a guard meta-test: the gate scripts are exercised against three fixture trees — skip-state (exit 0 + preview output), bind-state-clean (exit 0 + binding output), bind-state-dirty (one planted jquery import/artifact byte → exit 1). Add one sentence to KC 10 and KC 13: "the guard's skip/bind/red paths are covered by the S0 meta-test fixture (three repo states), so the bind branch is proven before S6." Apply the same pattern to `check-bundle-size.mjs` (fixture artifact over cap → exit 1) and the doc fence.

**MF-2 — Two-directional ratchet: no named artifact implements ALLOW−JQ, no test can fire it.**
Sections: Key Components 10 ("the ratchets are two-directional: the gate fails not only on a new jquery consumer/standalone (additions) but also when an allowlist/baseline entry's file no longer matches reality (ALLOW−JQ ≠ ∅ — forgotten shrinks surface in the slice that migrated the consumer, not at S6)"), Key Components 13 (S0 amendment list names only "the new CONST-P6 clause and the CONST-P1 final predicate"), TESTS item 4/Implementation Plan done-gate line. Slices: S0 (amendment), S1–S5 (per-slice deltas).
Verified: the constitution check @ f2ab61e is `comm -23` additions-only; `check-bundle-size.mjs` is byte-caps; no section names the artifact that compares ALLOW−JQ / baseline−actual. The per-slice "done-gate grep pins the exact expected contents" is prose unless the pin is a script; and between done-gates nothing standing catches a shrink that lands without its allowlist edit (e.g., a stray mid-slice commit migrating a consumer). As written, KC 10's claim ("surface in the slice that migrated the consumer") is unverifiable — direction-2 has no owner, which is precisely the forgotten-shrink blindness SQ-SF-6 was filed against.
Suggested fix: (a) KC 13's S0 amendment list gains "CONST-P1 sdd-check amended to bidirectional (`comm` in both directions) and the CONST-P6 check authored with its baseline file as the comparison substrate" — the ratchet direction claim then lives in a named, runnable artifact riding spec-craft + done-gate + CI from S0. (b) TESTS item 2 (S0) gains the direction-2 red test: fixture with an allowlist entry whose file no longer matches reality → exit 1 (mirrors MF-1's fixture). (c) Implementation Plan done-gate line reworded: "the slice's grep predicates" → "the slice's scripted allowlist/baseline pin (expected contents embedded in the slice spec's sdd-check)".

**SF-2 — "zero jquery imports repo-wide" predicate: pattern and exclusions undefined.**
Sections: Key Components 13 ("deps manifests ∅, sources+harness+build-configs ∅ — zero jquery imports repo-wide"), Executive Summary bullet, S6 cell. Slices: S0 (authoring), S6 (binding).

Suggested fix: KC 13 names the predicate shape: import-form patterns only (`from 'jquery'`, `import 'jquery'`, `require('jquery')`, deps.js `'jquery'` string entries, shim-map keys, optimizeDeps entries), include set = sources + `test/` + `build/` configs, exclude set = `*.md`, `.git`, `node_modules`, `dist`.

**SF-3 — notices-intact grep undefined.**
