## Findings ([must-fix] / [should-fix], each with section anchor + suggested fix)

**F1 [must-fix] — G6: CONST-P6 baseline arithmetic contradicts the repo.**
Anchors: Executive Summary "a new CONST-P6 ancestor-existence check with a shrinking baseline (3 → ∅)"; Key Components §13 "baseline `{desktop ua, touch ua, desktop winresize}` → ∅"; Slice table S0 "CONST-P6 skeleton (baseline 3)" and S6 "CONST-P6 baseline ∅".
Evidence (full file inventory of desktop.blocks + touch.blocks @ f2ab61e, excluding `*.examples`/`*.tmpl-specs`): standalone platform **JS** modules number 4, not 3 — `desktop.blocks/ua/ua.js`, `touch.blocks/ua/ua.js`, `touch.blocks/ua/__dom/ua__dom.js` (**missing from the baseline**; `common.blocks/ua` has no `__dom`), `desktop.blocks/jquery/__event/_type/jquery__event_type_winresize.js` (no `common.blocks/jquery/__event` exists). Additionally 2 standalone **template-only** modules that no slice mentions: `desktop.blocks/page/__conditional-comment/{bemhtml,bh}.js` (no common `__conditional-comment`), `touch.blocks/page/__icon/{bemhtml,bh}.js` (no common `__icon`). As written, the check either fails at S0 (finds more standalone files than the baseline admits) or can never reach ∅ at S6 (template modules unaddressed) — the same class of defect the assignment's arithmetic checks exist to catch.
Suggested edit: (a) declare CONST-P6's scope explicitly (runtime JS only vs including bemhtml/bh); (b) re-baseline to the true inventory (4 JS modules / 6 incl. templates); (c) add dispositions — S1 must create a common ancestor for `ua__dom` (or fold it into the common ua base) and say so in the S1 row; `page__conditional-comment` and `page__icon`: delete, hoist to common, or scope templates out with rationale.

**F2 [must-fix] — G1/G7: S0 gate staging breaks the per-slice green invariant (C2).**
Anchors: Executive Summary "Enforced per-slice by a bundle-budget gate + a no-jquery-in-artifact assertion landing in S0"; Key Components §10 ("no-jquery-in-artifact assertion + external/peer removal check" inside the S0 bundle gate); Key Components §13 (CONST-P1 final predicate "in S0, conclusive at S6"); Implementation Plan done-gate "(allowlist state, budget green)".
Between S0 and S6 jquery legitimately remains: peer dep + wrapper present (verified `peerDependencies: jquery ^4.0.0`, root export = `dist/desktop/bem-core.mjs` payload) and built artifacts import jquery through S5. Final-state assertions (no-jquery-in-artifact, peer/dev-dep removal, P1 final predicate "deps manifests ∅ … wrapper dirs gone") therefore cannot pass when "enforced per-slice" from S0 — S1–S5 CI red, slices not independently shippable, C2 violated. (The gz-byte caps are already correctly staged — "measured+10% today, final caps ~13/14 at S6" — the other assertions are not.)
Suggested edit: add one staging paragraph to KC §10/§13 and the S0 row: per-slice binding checks = gz-byte caps (ratchet) + CONST-P1 allowlist ratchet; the no-jquery-in-artifact assertion, external/peer removal check, and CONST-P1 final predicate activate at S6 (or auto-activate once the allowlist reaches ∅).

**F3 [should-fix] — G5: pointerevent normalization silently dropped instead of closed with evidence.**
Anchor: Key Components §6 (decomposition list omits it); PRD Problem Statement + PRD OQ3.
Repo @ f2ab61e: zero pointerevent code anywhere (`grep -i pointer` across common.blocks/desktop.blocks/touch.blocks → prose in `functions.*.md` only). The omission is correct, but G5's goal text lists it as one of four concerns and PRD OQ3 asks where it lands — an implementer or plan-review leg reading only the design cannot tell "dropped" from "missed".
Suggested edit: one line in KC §6 and a closed entry in the design's Open Questions: "Pointerevent normalization: moot — no pointer code exists at v5-base (grep-verified @ f2ab61e); PRD Problem Statement item and OQ3 retired."

**F4 [should-fix] — G3: loader semantics mapping incomplete; PRD "timeout" is stale and uncorrected.**
Anchor: Interface → "Loader surface" ("`loader(url, success?, error?)` → promise …; US6 migration line").
Current `loader_type_js.js` (62L) has no timeout (PRD G3's parenthetical is factually wrong about today), and carries in-flight dedup + loaded-cache semantics (loading/loaded Maps) plus a `file:`-protocol `'http:'` prefix fix — none mapped in the design. `import()` provides dedup/cache natively via the module map; the file: hack dies. Without the mapping, the parity claim ("semantics … provided via import()") is unauditable.
Suggested edit: add a semantics table to the Loader surface — async ✓ (import); error ✓ (rejection → error cb); timeout: none exists today → dropped (correct the PRD parenthetical); dedup + once-only cache → native import() module-map semantics; file:-protocol hack removed.

**F5 [should-fix] — G2: retained UA-driven branches lack the "documented justification".**
Anchor: Interface → "env / ua surface" ("`platform`, `ios`, `android`, `browser`, `screenSize`, `svg` memoized").
The design documents what survives but not why it is a legitimate UA-driven branch; the justification (Q5 audit: the only consumers are touch `ua__dom` platform modifiers; platform identity is not a capability question) lives only in the PRD clarification.
Suggested edit: one sentence in the env surface citing the audited consumer inventory as the documented justification, and name the S1 emulation-parity tests as the G2 "tests" leg.

**F6 [should-fix] — G1/G7: S4 interim jquery carrier unstated.**
Anchors: Slice table S4 row (−2: `__events`, `__events_type_dom`) together with Risks row 1 ("native dom-events while bem-events still ride jQuery").
If `i-bem-dom__events.deps.js` drops jquery at S4, the interim bem-event path must import jquery from some allowlisted file until S5 — presumably `__events_type_bem.deps.js` (allowlisted until S5), but the design never says so; the −2 delta's truthfulness hangs on it.
Suggested edit: add to the S4 row/spec: "interim: `__events_type_bem.deps.js` remains the sole jquery carrier until S5" (or equivalent re-homing note).

**F7 [should-fix] — G7: TESTS "New" enumeration omits S3.**
Anchor: Implementation Plan → TESTS checklist item 2 (lists S0, S1, S2, S4, S5, S6).
Suggested edit: add S3's new tests — promise-return semantics, error-callback wiring, ES-only rejection behavior, deprecated deep-import re-export once-warn.
