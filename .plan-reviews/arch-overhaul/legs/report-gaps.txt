  ## Summary                                                                  
                                                                              
  The PRD is strong on jquery/ua/loader/inherit strategy and strangler        
  discipline, but it has                                                      
  material gaps in five areas the repo state forces: (1) the **public API is  
  jQuery-typed**, so                                                          
  G1 collides head-on with CONST-P4 and the PRD never says what replaces      
  jQuery types in                                                             
  signatures; (2) the **verification anchor is missing** — tag v5-base does   
  not exist in this                                                           
  clone or on origin, and the touch platform is never tested; (3) **one slice 
  premise is stale** —                                                        
  pointerevent normalization doesn't exist anywhere in the repo; (4) the      
  **test harness itself**** is                                                
  ****a migration surface** (ym-authored specs, hand-maintained shim registry,
  hard-coded >400 gate)                                                       
  that no requirement covers; (5) **packaging/relic cleanup** (UMD dist,      
  exports map without                                                         
  touch entry, ENB-era test/dist + common.bundles, dead IE code in platform   
  levels) is                                                                  
  uninventoried beyond the benchmarks page.                                   
                                                                              
  ## Critical Gaps / Questions                                                
                                                                              
  1. **Public API is jQuery-typed — G1 as written is unimplementable without  
  an**** API-type                                                             
  ****strategy (CONST-P4 collision).** The PRD frames jquery as internal      
  substrate, but jQuery                                                       
  types leak across the public surface:                                       
      • common.blocks/i-bem-dom/i-bem-dom.js:342 — this.domElem = domElem;    
      every entity's                                                          
      domElem is a jQuery collection (.add() at :114, .not() at :227, jQuery  
      selector call                                                           
      this.domElem[select](selector) at :621).                                
      • bemDom.scope = $('body'), bemDom.doc, bemDom.win — public properties  
      holding                                                                 
      jQuery collections (i-bem-dom.js tail, set on jQuery DOM-ready).        
      • initOnDom / getFromDom accept HTMLElement|jQuery (i-bem-dom.js:1198-  
      1207);                                                                  
      updateTree/replace/append/prepend/insertBefore/insertAfter              
      consume/return jQuery                                                   
      collections (:1125-1185).                                               
      • The .bem() **jQuery plugin** is load-bearing in delegation:           
      common.blocks/i-bem-dom/__events/_type/i-bem-dom__events_type_dom.js    
      wrapperFn calls                                                         
      $(e.target).closest(...) and entityDomNode.bem(ctx) — $('.x').          
      bem('block') is a                                                       
      consumer-facing idiom.                                                  
      • common.blocks/dom/dom.js — contains(ctx, domElem) takes jQuery        
      collections;                                                            
      getFocused() returns $(document.activeElement).                         
      **Needed requirement:** an explicit public-surface type contract (accept
      Element|NodeList|Array|Document|Window? what type is domElem?           
      replacement for .bem()?)                                                
      with a CONST-P4 migration doc. OQ8 (export inventory) is related but    
      strictly smaller than                                                   
      this — it's the shape of every signature, not just the barrel.          
  2. **Tag **v5-base** does not exist.** git ls-remote origin (Realetive/bem- 
  core) shows only                                                            
  refs/heads/v5 @ f2ab61e; local git tag -l is empty. CONST-P5 and US5 ("diff 
  behavior                                                                    
  before/after against tag v5-base") are unverifiable as written. **Needed:** 
  a slice-0 ops                                                               
  requirement to create/push the tag (or pin the SHA) *before* the first      
  architecture slice,                                                         
  plus a documented per-slice before/after diff procedure (which tests, which 
  fixtures).                                                                  
  3. **Pointerevent normalization premise is stale — slice 4 has no repo      
  referent.**                                                                 
  find -name '*pointer*' → nothing. No jquery__event_type_pointerclick files  
  exist                                                                       
  (MIGRATION.md even cites that path as an example — it's gone). The only     
  surviving                                                                   
  __event_type_* is desktop.                                                  
  blocks/jquery/__event/_type/jquery__event_type_winresize.js,                
  IE8-only code (ua.msie && document.documentMode < 9) that is dead under C5. 
  The real                                                                    
  hidden dependency of __events_type_dom is **jQuery event normalization**    
  (event objects,                                                             
  .closest() traversal, .bem() lookup, delegation semantics), which the PRD   
  never names.                                                                
  **Needed:** re-anchor slice 4 (delete it as a pointerevent slice; fold in   
  "jQuery event                                                               
  normalization semantics parity" as an explicit deliverable of slice 5) and  
  correct the                                                                 
  Problem Statement / OQ3 accordingly.                                        
  4. **No browser matrix requirement; touch platform is never tested.**       
      • playwright.config.js — chromium only; CI (ci.yml) installs only       
      chromium. C5 says                                                       
      "modern evergreen browsers" but the PRD sets no matrix requirement      
      (webkit/firefox), no                                                    
      RTL/reduced-motion test story despite G2 mentioning RTL and input       
      modality.                                                               
      • build/vite.test.config.js pins platform: 'desktop' — the **touch build
      is**** never                                                            
      ****loaded by any test**. Touch-only modules (touch ua incl.            
      orientchange custom event,                                              
      touch.blocks/ua/__dom/ua__dom.js reading ~15 ua fields incl. screenSize,
      ios-subversion) have zero coverage. G2/G6 touch slices have no          
      verification harness.                                                   
      **Needed:** a verification-matrix requirement per slice (browsers ×     
      platforms), and a                                                       
      touch-platform harness decision (Playwright projects? separate vite test
      config?).                                                               
  5. **Spec corpus and harness are themselves a migration surface — no        
  requirement covers them.**                                                  
      • All 25 *.spec.js (common.blocks only) are authored in ym style        
      (modules.define('spec', [...])) and run through test/browser/modules-   
      shim.js;                                                                
      test/browser/entry.js **hand-maintains** the pre-registered module map. 
      ua, idle,                                                               
      loader_type_bundle, keyboard__codes are absent from the map → **no specs
      can**** exist                                                           
      ****for them today**. US2's "tests (Playwright) stay green" is vacuous  
      for the env/ua slice —                                                  
      G2 must *create* tests (also for loader_type_bundle).                   
      • test/browser.spec.js hard-codes expect(total).toBeGreaterThan(400) —  
      every slice that                                                        
      adds/removes specs trips this gate; needs a policy (drop the floor, or  
      make it dynamic).                                                       
      • i-bem-dom.spec.js:1813 ("modules.define patching") tests dynamic      
      redefinition —                                                          
      G4/G5 refactors must keep or consciously migrate this spec pattern.     
      • Spec files resolve dependencies **by module-name strings** via the    
      shim — refactors that

      unless the shim map

      **Needed:** a harness-evolution requirement attached to slices 1, 5, 7.
