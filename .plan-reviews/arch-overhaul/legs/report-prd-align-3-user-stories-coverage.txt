## Findings

### F2 [must-fix] — US3/G6 "docs tell me where shared behaviour goes" has no concrete carrier
- Story clause: US3 "docs tell me where shared behaviour goes"; G6 "the boundary is checked (lint/rule) **and documented**".
- Sections: "Proposed Design › Slice series" S6 row — "README/README.ru rewrite + docs bounded to an API-accuracy pass (…; content redesign out of scope, deferred post-6.0.0)"; "Risks and Mitigations" docs row — "content redesign out of scope, deferred post-6.0.0".
- Why: the only textual carriers are (a) an unscoped "README/README.ru rewrite" (content never enumerated — an engineer picking up S6 cannot know it must contain contributor guidance) and (b) a docs pass explicitly bounded to API accuracy with content redesign deferred. Neither names where the override-only rule, transformer form, or "shared behaviour goes in common.blocks" is documented for contributors; the explicit deferral actively reads as cutting the clause. The check half of G6 is well carried (CONST-P6, KC 9); the documented half is not.
- Suggested edit (S6 row + Risks docs row): scope the README rewrite to a named, bounded contributor section — e.g. "README/README.ru rewrite scoped to include 'Platform levels are override-only': shared behaviour lives in common.blocks, overrides must be transformer-form `export default function(prev)`, CONST-P6 ancestor-existence check (name + baseline semantics), and the plugin's build error naming both files; en/ru, anchor-fenced, 1-REQ-equivalent bound — bounded contributor guidance, not the deferred content redesign." Keeps NG-F1's deferral intact while giving G6/US3 a named carrier.

### F1 [should-fix] — US1 barrel casing (`BemDom` vs `bemDom`) unreconciled
- Story clause: US1 `import { BemDom } from 'bem-core'`.
- Section: "Interface › Root barrel" — "export { default as bemDom } from 'bem:i-bem-dom';" (+ D-7; S6 docs remap covers legacy `BEMDOM.*` → `bemDom.*`, not the PRD's `BemDom`).
- Why: the named root export exists (clause substantively covered), but the story's illustrative casing is never dispositioned — a reviewer walking US1 hits a silent mismatch.
- Suggested edit: one sentence in the Root barrel block: "PRD US1's illustrative `BemDom` casing resolves to `bemDom` (D-7: plain unprefixed DOM-flavor names; no invented casing); legacy `BEMDOM.*` → `bemDom.*` is the S6 docs remap."

### F3 [should-fix] — US3 "CI rejects" clause: CONST-P6 not wired into ci.yml
- Story clause: US3 "CI rejects any file in touch.blocks that doesn't correspond to a common.blocks ancestor".
- Sections: "Key Components 13" — "New CONST-P6 ancestor-existence check …" (runs as a constitution sdd-check at spec-craft/done-gate); "Implementation Plan › CI wiring" — "S0 — bundle gate appended to `build` job; api-pin joins the `test` node suite …" (CONST-P6 absent).
- Why: the check exists, rejects new standalones from S0 (baseline ratchet), and the skip/preview guard is specified — but the enforcement point for a plain contributor PR is the repo CI, and CI wiring never mentions it. The clause is covered only implicitly via the workflow done-gate.
- Suggested edit: add to the CI wiring S0 sentence: "CONST-P6 baseline check (and the CONST-P1 final predicate in its skip/preview form) ride the same `build` job as the bundle gate from S0" — or, if constitution-level enforcement is intended, state that explicitly and note the story's 'CI' wording is satisfied at done-gate + PR review only.

### F4 [should-fix] — US2/US5 per-consumer test carriers missing for `idle` and `__init_auto`
- Story clauses: US2 "tests (Playwright) stay green" (per consumer); US5 "including the 9 frozen consumers' scenarios".
- Section: "Implementation Plan › TESTS checklist" — "Pinned-green — existing specs cited by path that must pass (S4: …; S5: …; S3: loader_type_js.spec.js; S2: dom.spec.js)".
- Repo facts (@ f2ab61e): `common.blocks/idle/` has no spec corpus (deps/md/js only); no spec references idle; `__init_auto` (11 lines, `$(function(){ nextTick(init) })`) has no dedicated spec; idle is a platform-payload import (build/platforms/{desktop,touch}.js:48–49).
- Why: 7 of 9 consumers have named verification carriers; the idle and __init_auto migrations would land with only transitive coverage, unstated.
- Suggested edit: extend the TESTS parentheticals — "S2: dom.spec.js; idle has no spec corpus @ anchor — pin transitively via i-bem-dom.spec.js init flows or add a minimal idle unit (decide at S2 spec-craft)" and "S5: …; __init_auto pinned via the i-bem-dom.spec.js auto-init suites".

### F5 [should-fix] — US2 S5 trio per-file migration targets not itemized
- Story clause: US2 "which slice migrates it and to what (native DOM API / env module / registry)".
- Sections: S4 row — "interim: the remaining allowlisted trio (i-bem-dom, __events_type_bem, __init_auto) is the sole jquery carrier until S5"; S5 row outcome — "registry containment-walk emit; three Q10 parity caveats as named tests; events_type_bem 1013L + i-bem-dom 1854L green; allowlist = ∅" (no per-file disposition).
- Why: __events_type_bem → registry is explicit; i-bem-dom core (→ S2 facade + S4 engine remnants per KC 6 decomposition) and __init_auto (repo-verified jquery use = DOM-ready wrapper only) have derivable but unstated targets, so the −3 delta is less auditable than S4's interim note.
- Suggested edit: extend the S5 outcome cell mirroring S4's note: "−3 disposition: __events_type_bem → pure registry; i-bem-dom → remaining jquery substrate replaced by S2 facade + S4 engine (KC 6 decomposition completes); __init_auto → native DOM-ready (DOMContentLoaded/readyState) + nextTick(init)".

### F6 [should-fix] — US4 S3 closure predicate unnamed
- Story clause: US4 "I can verify completion mechanically."
- Sections: S3 row — "loader(url, success?, error?) …; loader_type_bundle deleted (bilingual note); classic-script semantic shift documented; internal-consumer audit"; Done-gate — "+ the slice's grep predicates (allowlist state, budget green)".
- Why: S3 is the only slice with no CONST-P1 delta, and the generic predicate parenthetical names only allowlist/budget — S3's slice-specific closure greps are implicit.
- Suggested edit: add to the S3 outcome cell: "closure predicates: zero `loader_type_bundle` references repo-wide; loader source contains dynamic `import(`; deprecated re-export present with once-warn."

### F7 [should-fix] — US6 migration line cites a stale `.get` call form
- Story clause: US6 "My runtime code that did `loader_type_js.get(url)` … or follows a documented one-line migration to `import()`".
- Section: "Interface › Loader surface" — "US6 migration line: `loader_type_js.get(url)` → `import(url)`".
- Repo facts (@ f2ab61e): `loader_type_js.js` default-exports a callable `(path, success, error)`; no `.get` exists in the loader dir, its spec (calls `loader('data:…', …)` directly), or any consumer; the docs (loader.en.md) document the callable form.
- Why: the design repeated the PRD's stale `.get` form verbatim — same class of stale premise the round-1 retirement gave the G3 "timeout" parenthetical, but this one survived into the migration line. The keeps-working arm is unaffected (the deprecated re-export preserves the callable shape; promise return is additive).
- Suggested edit: rewrite the line as "`loader(url, success?, error?)` → `import(url)` (PRD US6's `.get` form is stale @ the anchor — repo-verified, retired like the G3 timeout parenthetical); the deprecated deep-import re-export preserves the callable shape."
