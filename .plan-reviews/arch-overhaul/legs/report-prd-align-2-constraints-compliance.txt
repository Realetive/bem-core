## Findings

**[must-fix]** — none.

**F1 [should-fix] — CONST-P6 baseline says "3" in Data Model (stale pre-align-1 number).**
Trace: CONST-P3 / GA-F1 residue. Data Model 5 Ledgers: "CONST-P1 allowlist
(9→∅), **CONST-P6 baseline (3→∅)**" contradicts the verified and normative
KC13 "7 standalone module groups (12 files)" and the Exec Summary ("**7
standalone module groups → ∅**"). Same defect class prd-align-1 GA-F1 closed;
the fix missed this instance. Suggested edit: Data Model 5 → "CONST-P6
baseline (7→∅)".

**F2 [should-fix] — S0 root-export repurpose has no explicit consumer migration line.**
Trace: CONST-P4 / PRD C4. Position 1 + D-7 repurpose root `.` from today's
auto-init payload (verified: `exports."." = "./dist/desktop/bem-core.mjs"`)
to a "never auto-inits" barrel, with payloads moving to `./dist/{desktop,touch}`.
The change is documented as design, but the consumer-facing migration line
("side-effect consumers: `import 'bem-core'` → `import 'bem-core/dist/desktop'`
(or `./dist/touch`)") appears nowhere in the DOM/loader migration tables or the
S0 MIGRATION cell — it is only implied by the per-slice ledger discipline.
Suggested edit: add the entry-point migration line to Design position 3 (or the
S0 row's MIGRATION cell) so the break is enumerated like the other six.

**F3 [should-fix] — skip/preview guard mechanism for final-state predicates unspecified.**
Trace: PRD C3 (+ CONST-P1 staging). KC13 says the CONST-P1 final predicate
"runs in skip/preview mode until the allowlist reaches ∅ and is conclusive
(binding) at S6"; KC10 stages the bundle gate's final assertions likewise. The
intent is sound (verified GA-F2 fix), but the design never states the concrete
guard that keeps the S0-amended sdd-check exit-0 while the allowlist is
non-empty (e.g., predicate short-circuits to preview output + exit 0 when
ALLOW ≠ ∅; binding otherwise). Without it, the amendment is not yet
machine-checkable per the constitution's exit-0 = OK contract. Suggested edit:
one sentence in KC13 specifying the guard form (and mirroring it in KC10).

**F4 [should-fix] — pre-authorized S4+S5 fallback can breach the ≤12-REQ slice cap.**
Trace: PRD C2. Risks: "pre-authorized fallback: merge S4+S5 beads into one
convoy with two internal stages if interop exceeds ~2 REQ of shim work". S4
(8–12) + S5 (8–10) merged = one convoy of up to ~22 REQ, exceeding C2's
"≤12 REQ each" and the DAG section's "each convoy ≤12 REQ beads" as written.
Suggested edit: state that the fallback preserves two separately-gated internal
stages (each ≤12 REQ, convoy shippable only when both are green), or record an
explicit coordinator-approved cap waiver for that single fallback convoy.

**F5 [should-fix] — "v5-base/f2ab61e" conflation in the Retired subsection; no explicit anchor reconciliation.**
Trace: Q1 (binding). "Retired during prd-align-1": "grep-verified zero pointer
code at **v5-base/f2ab61e**" labels f2ab61e as v5-base, contradicting Q1
(v5-base = 7a9e932 ≠ f2ab61e). Verified: f2ab61e = 7a9e932 + the constitution
commit (parent chain), so evidence-greps at f2ab61e are valid proxies for the
7a9e932 parity anchor — but the doc never says so. Suggested edit: reword to
"@ f2ab61e (v5 head; = v5-base@7a9e932 + constitution commit, no blocks
touched between)" and add the same one-line reconciliation near the header's
"repo @ f2ab61e" evidence note.

**F6 [should-fix] — S0 constitution-amendment process not stated explicitly.**
Trace: PRD C1. The design introduces CONST-P6 and amends CONST-P1's predicate
in S0; CONSTITUTION.md's header requires such changes to pass a PR ("the PR is
the review"). Position 6 covers per-slice allowlist edits, but no sentence says
the two S0 constitution amendments themselves ride the S0 slice PR as that
review vehicle. Suggested edit: add to KC13 or the S0 row: "adding CONST-P6
and the CONST-P1 final predicate are constitution amendments carried by the S0
slice PR (constitution-header review process)".

**F7 [should-fix, PRD-side] — Q8's "declare in Constraints (C4) NOW" not reflected in PRD C-section text.**
Trace: Q8 (binding) / PRD C4. Q8 ordered the chromium-only + desktop-parity
matrix declared in the PRD's Constraints (C4) section; prd-draft.md's C4 text
still reads only "Behavior parity by default…". The binding Q8 amendment and
the design's D-15 satisfy the substance, so this is PRD hygiene, not a design
defect. Suggested handling: coordinator either patches the PRD C4 wording or
records that D-15 is the operative C4 declaration (one-line note in the PRD
review log). No design-doc edit required.
