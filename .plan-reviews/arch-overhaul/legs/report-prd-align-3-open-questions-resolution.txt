## Findings

**F1 [must-fix] Design-OQ 5 — deferral without a concrete decision point.**
Anchor: "## Open Questions" item 5 ("Shim-map ratchet home: constitution sdd-check vs plugin-test assertion — decide by whether non-owner agents may edit entry.js.") plus KC-12 and Implementation Plan TESTS item 4 ("Harness Δ — shim-map ratchet entries, count-floor policy changes, entry.js map edits").
Why: the deferral contract is "which slice's spec-craft decides, what the working position is in the meantime". OQ-5 names a decision rule but no slice, owner, or timing, and states no working position — yet the first shim-map ratchet entries land with the first spec-converting slice (per-slice Harness Δ, earliest S2), i.e. the decision has in-series consumers.
Suggested edit: rewrite OQ-5 to "Shim-map ratchet home: working position — plugin-test assertion (lives with vite-plugin-bem-levels tests; any slice may extend). Promote to a constitution sdd-check only if non-owner agents must be barred from editing entry.js. Decide at S0 spec-craft, before the first Harness Δ ratchet entry lands."

**F2 [should-fix] Orphan deferral: bada/wp field disposition lives only in body text.**
Anchor: "### env / ua surface" ("ua__dom also reads bada/wp for its platform modifiers; working position is they are encoded in env.platform (UA-derived, dedicated unit), ratified at S1 spec-craft") — added by prd-align-2 NG-F6 but never registered in the Open Questions inventory.
Why: walk-3 rule — every body deferral must match an inventory entry or be added; this one is well-formed (S1 point + working position) but orphaned.
Suggested edit: add as Open Question 10 ("env platform field encoding for bada/wp — ratify at S1 spec-craft; working position: encoded in env.platform") or fold into OQ-8's S1-ratify item with a cross-reference from the env/ua surface.

**F3 [should-fix] "Three Q10 parity caveats" count vs four enumerated parity items.**
Anchors: D-3 ("three caveats as named parity tests") and S5 row ("three Q10 parity caveats as named tests") vs KC-5 ("Parity contract: positional trigger args, flags.fns per-emit dedup, propagationStoppedDomNode containment rule, #1525 nested-same-type skip" = 4 items; Q10 names 3).
Why: count/pointer drift; a spec-craft copying "three" under-pins the contract (#1525 becomes an unlabeled extra).
Suggested edit: standardize on "four named parity tests: the three Q10 caveats (positional trigger args, flags.fns dedup, propagationStoppedDomNode containment) + the #1525 nested-same-type skip" in D-3, KC-5, and the S5 row.

**F4 [should-fix] "A named future phase" is never named.**
Anchors: Exec Summary ("native-class options are a named future phase"), D-2 ("native-class options a named future phase").
Why: honest in substance (no slice consumes native-class options; inherit frozen per Q4) but "named" without a name is unverifiable; the docs pass by contrast names its deferral ("post-6.0.0").
Suggested edit: name it — e.g. "a post-6.0.0 exploration convoy, opened only by a future PRD" — or drop "named".

**F5 [should-fix] Design-OQ 1 lacks a stated working position; body text commits to one.**
Anchors: OQ-1 ("per-push CI vs scheduled job — decide at S2 spec-craft") vs Implementation Plan CI wiring ("S2 — bench project." joining test-browser).
Why: the CI wiring implies per-push as the working position; the OQ should state it rather than leave the default discoverable only by inference.
Suggested edit: append "Working position: per-push (CI wiring line); a scheduled job is adopted only on runner-cost evidence, decided at S2 spec-craft."

**F6 [should-fix] Design-OQ 3 lacks a labeled working position.**
Anchors: OQ-3 ("Pick + pin in S4 specs") vs DOM type contract ("bemDom.scope/doc/win → lazy getters (body/document/window), never null").
Why: body text implies body-anchor (today's semantics) while documentElement is the candidate catching pre-body focus via focusin; carry the interim position explicitly.
Suggested edit: append "Working position: body (parity with today; see DOM type contract); document.documentElement is the candidate — pick + pin in S4 specs."

**F7 [should-fix] Design-OQ 6's "its slice" is undefined for a Non-Goal-frozen block.**
Anchor: OQ-6 ("stays until a spec exists or its slice decides fate. Keyboard internals are Non-Goal-frozen...") vs KC-8 (generation = S0–S1 tooling; "Generation must reproduce the keyboard__codes provision (payload-parity assertion) or record an explicit fate decision per OQ6").
Why: keyboard has no slice by design, so "its slice decides fate" names a decision point that never arrives; the concrete point (S0/S1 generation REQ) lives only in KC-8.
Suggested edit: reword OQ-6 to "stays; the S0/S1 generation REQ must either reproduce it (payload-parity assertion vs today's hand lists) or record the explicit fate decision (KC-8); silent drop via generation is forbidden; long-term fate revisited only by a future keyboard-spec convoy."

**F8 [should-fix] PRD OQ7 (dom block fate) disposition is implicit only.**
Anchors: PRD OQ7 ("does the tiny dom utility merge into i-bem-dom internals or stay public?"); carriers: Interface root barrel (export { default as dom }), deep-import inventory, KC-3 (internal DOM facade "surfaces through the bem:dom module graph"), S2 row ("dom/idle native").
Why: the Q3 answer (dom is public) is visibly carried, but the design never addresses the "merge into i-bem-dom internals" half — the reader must infer internals got a separate facade instead. Answered-but-unclear.
Suggested edit: one sentence in KC-3: "OQ7 disposition: dom stays public (Q3 inventory, root barrel); internal i-bem-dom helpers use this facade inside the bem:dom module graph — no merge into i-bem-dom internals."

**F9 [should-fix] $(node).bem() removal label drift (S5/S6 vs S5).**
Anchors: DOM type contract ("$(node).bem() plugin DELETED (S5/S6) — migrate to bemDom.initOnDom(...)") vs S5 row ("Pure-registry BEM events; $.fn.bem off"; slice titled "bem events + plugin") and S6 (wrapper deletion).
Why: "(S5/S6)" reads as either/or; the slice table puts the plugin off at S5 and wrapper deletion at S6.
Suggested edit: "DELETED at S5 (plugin off with the last jquery consumer; the wrapper itself is deleted at S6)".
