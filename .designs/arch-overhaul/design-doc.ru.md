## Резюме

Пересборка высаживается как **7 срезов-удушителей (S0–S6)**, каждый ≤12
требований, каждый независимо мержится в ветку `v5` с зелёными
lint/unit/browser-тестами. Критический путь: **S0 (забор верификации +
контракты) → S2 (периферия + DOM-фасад) → S4 (нативная делегация dom-событий)
→ S5 (BEM-события на чистом реестре) → S6 (удаление обёртки + принуждение
платформы)**; **S1 (env/ua)** и **S3 (лоадер)** идут параллельно от S0 и
вливаются в S6. Арифметика allowlist CONST-P1 закрывает срез на один раньше
прежней оценки: 9 позиций → −1 (S1) −3 (S2) −2 (S4) −3 (S5) = **∅ после S5**,
из-за чего S6 — чистые удаление, принуждение и подготовка релиза.

Ключевые результаты, все измерены или проверены grep-ом по репо @ f2ab61e
(голова v5 = анкер v5-base 7a9e932 плюс коммит конституции; между ними блоки не
трогались, поэтому grep-ы по f2ab61e — валидный прокси паритета для анкера):

- **Бандл потребителя падает ≈ 38.5 kB gz → ≈ 12–13 kB gz (−66%)** — один
  запрос, ноль peer-зависимостей (peer jquery@4 = измеренные 27.53 kB gz;
  нативная замена оценивается в +1–2 kB gz). Принудительно держится
  **стейджинговым** бандл-гейтом (S0): per-slice-биндингами являются только
  gz-кап ратчета (+ allowlist-ратчеты); ассерты «ноль jquery в артефакте» и
  «удаление jquery из peer/dev-зависимостей» **активируются на S6** — по факту
  существования обёртки + чистоты package.json, а не по пустоте allowlist
  (allowlist уже ∅ после S5, при этом jquery легитимно остаётся в payload до
  удаляющего коммита S6; привязка по ∅-allowlist забиндила бы ассерты на срез
  раньше и покраснела бы окно S5→S6 — финальные ассерты не могут пройти раньше,
  пока jquery легитимно присутствует).
- **Настоящий публичный API**: сегодняшний корневой экспорт — payload только из
  побочных эффектов с нулём именованных биндингов. Дизайн вводит
  платформо-нейтральный barrel именованных экспортов
  (`import { bemDom, env } from 'bem-core'`), закреплённый инвентарь
  deep-import-ов, нативный DOM-контракт `Element`/`Element[]` и
  api-pin-тест, делающий CONST-P4 механически исполнимым.
- **События без jQuery**: dom-события переезжают на движок нативной делегации
  per-scope (анкеры на скоуп, обход composedPath, компилируемые однократно
  матчеры class-токенов); BEM-события становятся **чистым реестром** с обходом
  контейнмента сущностей (Q10) — без `$.event.special`, без эмуляции
  синтетического баблинга.
- **Платформенные слои — override-only по построению**: новая проверка
  существования предка CONST-P6 со сжимающимся базлайном (**7 standalone-групп
  модулей → ∅**, инвентарь верифицирован @ f2ab61e — см. Ключевые компоненты
  13), принудительная валидация transformer-form в плагине для цепочек
  переопределений, и `ua` схлопывается из двух непересекающихся платформенных
  форков в общую базу (включая предка-элемент `__dom`) + touch-дельта.
- **`inherit` остаётся замороженным** (Q4=a) — нулевое изменение кода,
  закреплено существующими спеками; варианты нативных классов — именованная
  будущая фаза: исследовательский конвой после 6.0.0, открываемый только
  будущим PRD.
- **Один релиз 6.0.0** в конце (Q9), двуязычные секции MIGRATION накапливаются
  по срезам, `repository.url` чинится в S0.

## Постановка проблемы

Переносится дословно из исправленного PRD: архитектура библиотеки — всё ещё
дизайн 2016 года: jquery-обёртка (peer-зависимость на 30+ kB gz) как
DOM-подложка всего слоя `i-bem-dom` с 9 замороженными потребителями на ратчете
CONST-P1; платформенные форки со сниффингом UA, отвечающие не на те вопросы;
самописный лоадер на инъекции скриптов; нерешённый классический-ООП `inherit`;
монолит `i-bem-dom` на 1220 строк; платформенные слои, смешивающие override-ы
со standalone-логикой без принуждения. Цель — целевая архитектура плюс план
срезов-удушителей, полностью убирающий внутренний jQuery, модернизирующий
границы модулей и делающий платформенную границу машино-проверяемой — с
наблюдаемым поведением, равным тегу `v5-base` (7a9e932) всюду, где ни один срез
не документирует миграцию.

Форма DAG: `S0 → {S1, S2, S3}`; `S2 → S4 → S5 → S6`; `S1, S3 → S6`. Create-beads
моделирует S1 и S3 параллельными ветками, не серийной очередью. Колонка Deps и
эта строка несут один набор рёбер — транзитивно-редуцированные прямые рёбра
(S4 ← S2; S6 ← S1, S3, S5); create-beads вяжет прямые рёбра, замыкание
получается само.

### Дизайн-позиции (сквозные)

1. **Два продукта, два вида entry.** Платформенный payload побочных эффектов
   (`dist/{desktop,touch}/bem-core.mjs`, авто-инициализация) и
   платформо-нейтральный barrel именованных экспортов API (`dist/index.mjs`,
   никогда не авто-инициализируется) — оба публичны и явно не смешиваются.
   Корень `.` становится API-barrel; payload переезжают в `./dist/desktop` и
   `./dist/touch`.
2. **Публичное — по инвентарю, внутреннее — по расположению.** Exports-map
   сужает `"./*"` → `"./common.blocks/*"` (+ перечисленные entry) в S0,
   непубличные пути перестают резолвиться (`ERR_PACKAGE_PATH_NOT_EXPORTED` /
   Vite на этапе сборки), при этом все существующие публичные deep-import-ы
   работают. Внутренние модули живут внутри elem-пространств имён
   потребляющих блоков, не становясь API. Wildcard — осознанный
   совместимый-наднабор, а не контракт: api-pin-тест + CONST-P4 полицируют
   закреплённый инвентарь (Interface → набор deep-import-ов). Путь `inherit`
   — **внутренний-но-терпимый** под wildcard (замороженный внутренний по
   Q4/D-2) — не часть публичного контракта; будущее сужение, его убирающее,
   требует заметки миграции CONST-P4.
3. **Паритет поведения по умолчанию, документированные ломки допустимы**
   (C4/CONST-P4): каждое изменение сигнатуры едет с двуязычной записью
   MIGRATION в том же срезе; трипваером — api-pin-тест. Переименование
   root-экспорта в S0 перечислено как любая другая ломка: сегодняшний корень
   `.` — desktop-payload побочных эффектов (`exports."." =
   "./dist/desktop/bem-core.mjs"`); потребители побочных эффектов мигрируют
   `import 'bem-core'` → `import 'bem-core/dist/desktop'` (или `./dist/touch`)
   — ячейка MIGRATION S0 несёт эту строку **и** строку сужения exports (сегодня
   `"./*": "./*"` резолвит любой путь от корня — `desktop.blocks/…`,
   `touch.blocks/…`, `test/…`; после сужения пути от корня за пределами
   `./common.blocks/*` + перечисленных entry не резолвятся).
4. **Никакого MutationObserver, никогда.** Живые коллекции остаются
   ленивально-вычисляемыми с явной инвалидацией в санкционированных точках
   мутаций (`bemDom.init/destruct/update/append/...`). Состояние по нодам
   мигрирует в WeakMap (классы утечек умирают по построению); учёт
   многонодовых сущностей сохраняет явный teardown.
5. **Селективное потребление = плагин.** Полный tree-shaking структурно
   невозможен с побочными эффектами деклараций/регистраций и вне охвата.
   Официальная история per-app: потребители запускают
   `vite-plugin-bem-levels` (публичен в `./build/plugins/*`) в своём конфиге
   Vite. US1 остаётся в охвате «без jQuery в бандле».
6. **Каждый срез оставляет `v5` собираемым и тесты зелёными** (C2); PR каждого
   среза правит allowlist конституции тем же коммитом (клауза CONST-P1 о PR);
   каждый срез несёт чек-лист TESTS (см. План реализации).

### Корневой barrel (платформо-нейтральный, никогда не авто-инициализируется)

```js
export { default as bemDom } from 'bem:i-bem-dom';        // Block, Elem, declBlock,
                                                          // declElem, declMixin,
                                                          // entities, init, destruct,
                                                          // detach, update, replace,
                                                          // append, prepend, before,
                                                          // after, getFromDom,
                                                          // initOnDom, scope, doc, win
export { default as BemDomCollection } from 'bem:i-bem-dom__collection';

export { Emitter, Event } from 'bem:events';

                                                            // barrel в S3 (путь мода

export { default as ua } from 'bem:ua';                   // S1, депрекейтед-алиас
```

Простые имена = DOM-флейвор (доминирующая поверхность авторинга);
vanilla-only авторинг `i-bem` остаётся документированным deep-import-ом.
Никаких выдуманных/префиксных экспортов. Иллюстративный кейс `BemDom` из
PRD US1 разрешается в `bemDom` (D-7: простые непрефиксные имена DOM-флейвора,
без выдуманного кейса); легаси-ремапа `BEMDOM.*` → `bemDom.*` —
документационный проход S6.

### Поддерживаемый инвентарь deep-import (закреплённый набор)

i-bem (`.vanilla.js`, `__internal`, `__collection`), i-bem-dom (основной,
`__collection`, `__events`(+`_type/{dom,bem}`), `__init`(+`_auto`)), events
(`.vanilla.js`, `__channels`, `__observable`(+`_type/bem-dom`)), `dom`,
`loader` (корневой `loader.js`, канонический с S3 — путь мода
`loader_type_js` удаляется коммитом S3, D-16), `env`, `ua` — всё под
`common.blocks/`. `inherit` НЕ в закреплённом наборе:
внутренний-но-терпимый под wildcard `./common.blocks/*` (замороженный
внутренний по Q4/D-2); его будущее удаление требует заметки миграции
CONST-P4. Пути `jquery` исчезают на S6 (pin-тест затем ассертит отказ
импорта). `./build/plugins/*`: дефолтный экспорт плагина
`bemLevels({platform, levels, rootDir?}) → Vite Plugin`.

### DOM-контракт типов (сжатая таблица миграции CONST-P4)

> Публичные DOM-типизированные значения — нативные `Element` или `Element[]`.
> Множественные — обычные массивы, в порядке документа, дедуплицированные,
> **статичные снапшоты** — считать неизменяемыми; перечитывать после
> DOM-изменений. Никаких живых коллекций в публичном API.

- `entity.domElem` → замороженный снапшот-геттер `Element[]` (внутреннее
  хранилище приватно).
- `bemDom.scope/doc/win` → ленивые геттеры (`body`/`document`/`window`),
  никогда null; поведение пустого body сохранено (ленивый геттер резолвит
  пустое множество, пока body не существует — паритет с сегодняшним;
  полировка explicit-throw выброшена в plan-review-2 SC-6: ненаблюдаемая
  ломка на краевом пути, никто не просил).
- `bemDom.init(ctx?)` принимает `Element | Element[] | string-селектор`,
  возвращает `Element[]`; `destruct/detach/update/replace/append/...`
  принимают `Element | Element[]`; контент: `string(html) | Element |
  Element[] | entity`; вставки возвращают `Element[]`.
- `dom.getFocused()` → `Element`; `dom.contains(ctx, node)` — семантика
  any-in-any; `isFocusable/isEditable` принимают `Element`.
- `e.bemTarget` → `BemDomEntity | null`; плагин `$(node).bem()` УДАЛЯЕТСЯ на
  S5 (вместе с последним jquery-потребителем; сама обёртка удаляется на S6) —
  мигрировать на `bemDom.initOnDom(node, Block, params)`.

### Поверхность env / ua

`env`: только геттеры (`ua` — сырая строка как диагностика; `platform`,
`ios`, `android`, `browser`, `screenSize`, `svg` — мемоизированные;
`width`, `height`, `landscape` — живые) + CustomEvent `orientchange` на
window. **UA-производные против capability-проб (обоснование G2):**
`platform`/`ios`/`android`/`browser` — производные строки UA и сохранены
осознанно — их читает аудит-инвентарь потребителей (Q5: платформенные
модификаторы touch `ua__dom`), а идентичность платформы — не capability-
вопрос; каждый несёт обоснование в спеке S1 + выделенный юнит, а
паритет-тесты эмуляции S1 — это «тестовая» нога G2. `svg`/`screenSize`/
`width`/`height`/`landscape` — capability/живые пробы. **Полнота судьбы
полей (строгость Q5 бьёт в обе стороны):** каждое поле, читаемое
аудит-потребителем, получает явную диспозицию в спеке S1 — `ua__dom` также
читает `bada`/`wp` для своих модификаторов; рабочая позиция — они
кодируются в `env.platform` (UA-производное, выделенный юнит), ратифицируется
на spec-craft S1 — без молчаливых дыр внутри переписывания замороженного
потребителя. `ua`: Proxy-алиас, живая пересылка, удалённые поля (`msie`,
`dpr`, `flash`, `iphone`, `ipad`, `webkit`, …) варнят один раз и возвращают
`undefined`. Контракт алиаса — чтение свойств; деструктуризация/spread не
поддерживаются по построению (отмечено в спеке S1 — plan-review-2 F6).
`env.browser` держит ключи `opera`/`chrome` один релиз (паритет), умирает с
алиасом.

### Поверхность лоадера

`loader(url, success?, error?)` → промис namespace модуля; строка миграции
US6: `loader(url, …)` → `import(url)` — форма `.get` из US6 PRD устарела @
анкер (проверено по репо: `loader_type_js` дефолт-экспортирует вызываемое
`(path, success, error)`; метода `.get` нет ни в лоадере, его спеке, ни у
потребителей — закрыто как и скобка про таймаут G3); новый корневой модуль
сохраняет вызываемую форму (старый путь мода удаляется сразу — двуязычная
запись MIGRATION несёт старый/новый пути; моста на один релиз нет, D-16),
возврат промиса — аддитивен. Документированный смысловой сдвиг: **только
ES-модули** — классические скрипты, определяющие глобалы, больше не
исполняются.

Маппинг семантики (старый `loader_type_js` @ f2ab61e → новый):

| старое поведение | судьба |
|---|---|
| асинхронная загрузка | ✓ `import()` |
| сообщений об ошибках (колбэк `error`) | ✓ реджект → колбэк |
| дедуп в полёте + кэш загруженного-однажды (Map-ы `loading`/`loaded`) | нативная семантика module-map `import()` |
| фикс префикса `'http:'` для `file:`-протокола | удалён (Vite/Node резолвят `file:` нативно) |
| кросс-доменные URL скриптов (классическая инъекция грузит их без CORS сегодня) | изменение поведения — динамический `import()` требует CORS-заголовков на цели; аудит внутренних потребителей S3 подтверждает ноль кросс-доменных URL лоадера; строка MIGRATION (plan-review-2 F3) |
| таймаут | **никогда не существовал** — скобка про «таймаут» в G3 PRD устарела (проверено по репо: таймаута в `loader_type_js` нет); выброшено. Таймаут был бы новой фичей (Non-Goal) или однострочным враппером `Promise.race` — на усмотрение спеки S3 |

### UX ошибок при неправильном использовании

Непубличный путь → `ERR_PACKAGE_PATH_NOT_EXPORTED` (Node) / нерезолвленный
импорт (Vite), рано и греппабельно · удалённое поле ua → `undefined` +
однократный warn · `bemDom.init` до DOM → ленивый scope (пуст до
существования body — паритет) · немодульный URL лоадера → реджект import() +
двуязычная пометка · override написан неверно → **ошибка сборки**, называющая
оба файла (валидация плагина).

   компонуются сгенерированными transformer-barrel-ами (`_module =
   redefN(_module)`); платформенные entry генерируются из реестра скана
   (нога данных D3-c). `.deps.js` остаётся **документированным манифестом,
   никогда — входом сборки** — lint схемы+резолюции не планируется (вырезан
   в plan-review-2 SC-1: манифест не имеет внутриреповых механических
   потребителей кроме grep CONST-P1, который уже потребляет его как субстрат
   ратчета); мёртвый внутриплагинный `bemEntityToModuleName` удаляется как
   подсадка release-prep S6 (отложено из S0 в plan-review-2 SC-2 — от него
   ничего не зависит вниз по потоку).
2. **Модель override-ов (нормативный глоссарий)**: *база* (индекс цепочки
   0), *transformer override* (индекс ≥1, ОБЯЗАН быть
   `export default function(prev)` — иначе ошибка сборки), *side-effect
   уточнение* (без дефолтного экспорта, только индекс 0), *standalone
   платформенный модуль* (без общего предка — только базлайн CONST-P6).
3. **Рантайм-реестры**: `bem.entities` (имя → класс, пишется побочными
   эффектами импортов `decl*` — внутренний, запинен), отложенная очередь
   `initFns`, гард `_processInit`, путь живой мутации класса `inherit.self`
   сохранён (спека:1813).
4. **Хранилища живых индексов** (после декомпозиции):
   `WeakMap<Node, params>`, `WeakMap<Node, entity>` + явная
   `Map<uniqId, Set<Node>>` для многонодовых сущностей; кэши элементов на
   сущность + инвалидация `_findBackRefs` без изменения семантики.
5. **Реестры (ledgers)**: allowlist CONST-P1 (9→∅), базлайн CONST-P6 (7→∅),
   allowlist shim-мапы (сжимается), JSON-ы бюджетов бандла/бенчей (ратчет),
   двуязычные пары MIGRATION/CHANGELOG (под забором паритета анкеров). Диффы
   ратчетов по серии И ЕСТЬ машиночитаемая история миграции.
6. **Мост спек-харнесса**: shim-мапа ESM→ym (ратчетится), пока не останется
   ноль `modules.define` в спеках; учёт регистраций заменяет пол `>400`
   (смена политики принадлежит harness-коммиту S2 — KC 12; механика по
   OQ-11).

`S2→S4→S5→S6`, `{S1,S3}→S6`; каждый конвой ≤12 REQ-бусин; дельты allowlist,
чек-листы TESTS и ячейки MIGRATION из таблицы срезов выше становятся
критериями готовности по срезам; S1 и S3 мутируют barrel/pin-инвентарь на
непересекающихся строках экспорта (S1 +env/+ua; переключение лоадера S3) —
порядок мержа между ними свободен, толерантность ребейза записана в обеих
спеках (обоснование гонки ручных правок KC 8 применимо к генерации, не к
этим построчно-непересекающимся правкам); спека S4 преавторизует фолбэк
слияния S4+S5. **Преавторизация переполнения (plan-review-2 F7/F10):** S0
при >12 REQ на spec-craft расщепляется на S0a (забор + контракты: barrel,
пин, сужение exports, гейты, doc-забор, поправки конституции) и S0b
(генерация + инструментарий валидации transformer-form плагина) — оба
приземляются до веера S1/S2/S3 (S2/S3 строго нуждаются в генерации S0b;
S1 — в barrel/пине S0a). S6 при >12 REQ расщепляется на S6a (удаление +
принуждение + финальные гейты) и S6b (подготовка релиза + доки/README +
консолидация реестров) — S6a раньше S6b; расщепления посреди полёта больше
нигде не авторизованы. **Протокол отката (F8):** mid-series revert-ы —
стековые: откат среза N при приземлённом N+1 требует отката N..M; гейты
перещёлкиваются по git-отслеживаемому состоянию и остаются
самосогласованными; краснота после частичного отката приходит от кода, не
от гейтов.

## Открытые вопросы

1. Бенч-проект: CI на каждый пуш против запланированной джобы (цена против
   латентности регрессий) — решить на spec-craft S2. Рабочая позиция: на
   каждый пуш (строка CI-привязки); запланированная джоба принимается только
   по фактам стоимости раннеров.
2. Финальные капы бандла: остаются в `specs/bundle-budget.json`
   (CI-принуждение) против повышения до sdd-check конституции на S6.
   Рабочая позиция: JSON + CI; конституция держит только
   no-jquery-предикат.
3. Анкер `bemDom.scope` для биндингов уровня класса после ESM: `body`
   (сегодня) против `document.documentElement` (ловит pre-body focus через
   focusin). Рабочая позиция: `body` (паритет с сегодня — см. DOM-контракт);
   выбрать и запинить в спеках S4.
4. Проверка доказательств parseHTML (запасной выход D-11): результат
   прицельного grep/спек-аудита решает паритет против scripts-inert —
   первый REQ S2.
5. Дом ратчета shim-мапы: рабочая позиция — ассерт в тестах плагина (живёт
   с тестами vite-plugin-bem-levels; любой срез может расширять). Повышать
   до sdd-check конституции, только если не-владельцев надо запретить
   править entry.js. Решить на spec-craft S0, до первой записи Harness Δ
   (раньше всего S2).
6. Тестовое обеспечение `keyboard__codes`: остаётся; REQ генерации S0 обязан
   либо воспроизвести его (ассерт паритета payload против до-S0 ручных
   списков), либо записать явное решение о судьбе (Ключевые компоненты 8);
   молчаливый дроп через генерацию запрещён; долгосрочная судьба — только у
   будущего конвоя keyboard-спеки (внутренности клавиатуры заморожены
   Non-Goal — ни один срез серии ими не владеет).
7. Зависит ли что-то вне спек-корпуса от рантайм-переобъявления
   (`inherit.self`)? Pin-тест S0 записывает мутацию `bem.entities` как
   внутреннюю.
8. Легаси-ключи `env.browser` (`opera`/`chrome`): подтверждено время жизни
   один релиз (умирают с ua-алиасом) — ратифицировать в спеке S1.
9. Именование barrel `dist/index.mjs` и пути payload-entry (`./dist/desktop`
   против `./desktop`): косметика, ратифицировать в спеке S0.
10. Кодирование `env.platform` для `bada`/`wp` (поля платформенных
    модификаторов `ua__dom`): рабочая позиция — кодируются в
    `env.platform` (UA-производное, выделенный юнит); ратифицировать на
    spec-craft S1 (см. «Поверхность env / ua»). Зарегистрировано здесь,
    чтобы у отсрочки в основном тексте была запись в инвентаре.
11. Механика реестра учёта регистраций (замена пола `>400`, KC 12 —
    plan-review-3 T-SF-7/C-MF-2): дом реестра — рабочая позиция:
    закоммиченный JSON с ключом по пути спеки, сжимающийся ратчет,
    ассертится домом тестов плагина, выбранным для shim-мапы (OQ-5);
    определение мягкого пола живости — рабочая позиция: всего
    зарегистрировано ≥ N% от реестра на старте спеки; владелец обновлений —
    срез, выполняющий Harness Δ. Решить на spec-craft S0; сама смена
    политики приземляется в harness-коммите S2 (S4/S5 расширяют учёт по
    конвертациям).
