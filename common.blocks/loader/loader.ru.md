# loader

Блок `loader` загружает ES-модуль по URL с помощью динамического `import()`.

## Обзор

| Функция | Возвращаемое значение | Описание |
| ----------- | --- | -------- |
| <a href="#methods-loader">loader</a>(`url {String}`, `[success {Function}]`, `[error {Function}]`) | `Promise` | Загружает ES-модуль по URL. |

### Публичные технологии блока

Блок реализован в технологиях:

* `js`

## Описание

<a name="methods"></a>

### Загрузка ES-модуля

<a name="methods-loader"></a>

Функция `loader(url, success, error)` — тонкая обёртка над динамическим
`import()`:

* `url {String}` — URL загружаемого ES-модуля. Обязательный аргумент.
* [`success {Function}`] — вызывается с namespace модуля, когда модуль загружен.
* [`error {Function}`] — вызывается с ошибкой загрузки, если загрузка не удалась.

Функция возвращает промис `import()`, который разрешается namespace модуля:

```js
import loader from 'bem:loader';

// форма с промисом
loader('./chunks/extra.mjs')
    .then(module => { /* module.default, module.namedExport, … */ });

// форма с колбэками
loader('./chunks/extra.mjs',
    module => { /* загружен */ },
    error => { /* ошибка */ });
```

### Семантика

* **Только ES-модули.** URL должен указывать на корректный ES-модуль,
  отдаваемый с JavaScript MIME-типом. Классические скрипты, которые лишь
  определяют глобальные переменные, больше не загружаются через этот блок.
* **CORS обязателен.** Динамический `import()` применяет правила CORS к
  кросс-доменным целям: сервер-цель должен отдавать соответствующие заголовки
  `Access-Control-Allow-Origin`. Прежняя реализация на инъекции скриптов этого
  не требовала.
* **Нативное кэширование в module map.** Повторные вызовы с одним URL
  переиспользуют module map браузера: повторные запросы дедуплицируются,
  загруженные модули отдаются из кэша.
* **Без таймаута.** Загрузка следует сетевому поведению браузера; таймаут
  загрузки не устанавливается.
